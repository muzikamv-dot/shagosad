# ШагоСад — паспорт проекта

## Что это
Уютная коллекционная игра о шагах для Android. Шаги → вода → цветок → открытка в галерею.
Офлайн, без сети, без аккаунтов.

- package: `com.dsh.stepcounter`
- launcher label: **ШагоСад**
- minSdk 26, targetSdk 35, compileSdk 35
- версия: versionCode 79 / versionName 9.5
- подпись: `~/.dsh/secrets/stepkey.keystore` (alias stepkey, пароль хранится локально в `secrets.local.ps1` (в репозиторий не попадает))
  резерв: `~/stepapp-keys/stepkey-backup.keystore`

## Где что лежит
- сборка: `~/stepbuild/build.sh` (aapt2 → javac → d8 → zip → apksigner)
- исходники: `~/stepbuild/stepapp/src/com/dsh/stepcounter/`
- ресурсы: `~/stepbuild/stepapp/res/`
- android.jar: `~/stepbuild/sdk/android-35/android.jar`
- генераторы графики: `~/stepbuild/tools/`
- готовый APK: `/storage/emulated/0/Download/Шагомер/ШагоСад.apk`

ВАЖНО: рабочая папка сессии (`workspaces/incoming`) периодически чистится.
Всё постоянное держать только в `~/stepbuild`.

## Сборка

### На компьютере (основной способ, Windows)
```
C:\Godot\stepbuild\build.cmd            # собрать APK
C:\Godot\stepbuild\build.cmd -Install   # собрать и поставить на телефон
C:\Godot\stepbuild\build.cmd -FreshRes  # пересобрать все 3672 ресурса
```
Те же шаги, что в `build.sh`, но на локальных JDK 17 и Android SDK 36.
Холодная сборка (все ресурсы) ~62 с, обычная после правки кода ~13 с.
Ресурсы кэшируются в `.rescache` и пересобираются, когда меняется файл в `res/`.
Скрипт сверяет отпечаток сертификата с установленным APK: чужой ключ → сборка падает,
а не даёт APK, который не встанет поверх.

### Выгрузка на телефон: папка `Download/Шагомер`
Это папка «для людей» — оттуда APK пересылают. Раньше она обновлялась руками, и в ней
остался APK от 24.10 на 41 МБ (сборка до выноса спрайтов), поэтому человек получил
старую версию. Теперь `build.ps1 -Install` после установки сам кладёт туда:

| файл | что внутри |
|---|---|
| `ШагоСад.apk` | ровно та сборка, что установлена (скрипт сверяет SHA-256 на устройстве) |
| `ПАСПОРТ-ПРОЕКТА.md` | этот документ; строка «версия:» берётся из манифеста при сборке |
| `ЧИТАЙ-МЕНЯ.txt` | шаблон из `stepbuild/distribution/ЧИТАЙ-МЕНЯ.txt`, `@VERSION@` подставляется |
| `версия.txt` | версия, дата сборки и SHA-256 APK |
| `исходники-шагомер.zip` | `src`, `res`, манифест, паспорт и `build.ps1` |

Правило: **файл в этой папке обязан совпадать с установленным приложением**. Если
версия на телефоне и в папке разошлись — значит APK выгружали не скриптом.
Проверка одной командой:
```
adb shell sha256sum '/sdcard/Download/Шагомер/ШагоСад.apk'
```
и сравнить с SHA-256 из вывода сборки.

Шаблон «ЧИТАЙ-МЕНЯ» лежит в репозитории (`distribution/`), а не только на телефоне,
чтобы текст правился в одном месте и не расходился с папкой.

### Публикация на GitHub
Раздача и хранение — репозиторий **https://github.com/muzikamv-dot/shagosad** (публичный, MIT).
Копию APK на рабочем столе больше не держим: после изменений проекта всё уходит на GitHub.

```
C:\Godot\stepbuild\publish.ps1                     # коммит с сообщением по версии
C:\Godot\stepbuild\publish.ps1 -Message "что нового"
```

(мастер-копия — `distribution\README.md`), `build.ps1` и кладёт свежий APK
в `dist/ШагоСад-<версия>.apk`, удаляя прежний. Потом `git add`, `git commit`, `git push`.

Локальный клон: `C:\Godot\_github\shagosad`. Токен лежит вне репозитория —
`C:\Godot\_from_phone\gh_token.txt` (в `.gitignore` его нет, потому что он вообще
не в проекте).

## Игровые константы
- видов цветов: **365** (`Species.COUNT`), форм-архетипов 24 (`id % 24`)
- состояний растения: **11** (0 семя, 1..10 рост, 10 цветок)
- поливов до цветка: **10**
- лейка = `goal / 10` шагов (`GameState.stepCost()`, минимум 100)
- норма по умолчанию: 10 000 (диапазон 1 000…100 000)
- задание «пройти шагов» = **80% нормы** (`questTarget`)
- очки: +100 за цветок, +60 за достижение, +40 за дневное задание, +300 за недельное
- вода начисляется ТОЛЬКО из шагов (никаких бонусов за задания/достижения)
- смена нормы: прогресс к лейке пересчитывается пропорционально

## Сброс прогресса (важное правило)
- `GameState.GAME_VERSION` — версия правил. Меняется → прогресс сбрасывается один раз.
- `versionCode` приложения прогресс НЕ сбрасывает (это специально убрано).
- ручной сброс: Настройки → «Сбросить прогресс» → ввод слова СБРОС.
- тестовые инструменты: 7 тапов по строке версии в настройках.

## Данные
- `garden.json` в filesDir: вода, очки, серия, букет, достижения, открытки, этапы, цель, waterProgress/stepsMark
- `journal.txt` в filesDir: журнал шагов (время|метка датчика|значение)
- `avatar.png` в filesDir: фото-аватар
- настройки в SharedPreferences `steps`: goal, service_enabled, manual_steps, onboarding_off, seen_version

## Экраны
- MainActivity: 5 вкладок (Шаги, Сад, Задания, Профиль, Достижения), свайп влево/вправо,
  анимация 300 мс (въезд на всю ширину), точки-индикатор, шестерёнка в шапке
- SettingsActivity: норма, сброс, разрешения, фон, тест (скрыт), версия
- ShopActivity: 8 рамок аватара за очки (150…1000)
- GalleryActivity: список сохранённых открыток
- CollectionActivity + CollectionView: сетка всех 365 видов (собранные цветными,
  остальные силуэтами), фильтры «Все / Собраны / Осталось», нажатие на собранный
  вид открывает открытку
- ChangelogActivity: история изменений по датам (`Changelog.java`)
- OnboardingActivity: обучение, ввод нормы, галочка «больше не показывать»
- StepService: опциональная foreground-служба (уведомление о шагах)
- StepWidget: виджет 2×2

## Графика

С версии 7.7 цветок рисуется **параметрической моделью** (`KawaiiPlant.java`), а не спрайтами:

- стебель — кривая Безье с сужением к вершине и изгибом;
- листья крепятся на узлах стебля, 4 формы (овальный, ланцетный, зубчатый, округлый),
  правая и левая стороны зеркальны, у каждого своя фаза качания;
- головка: кольца лепестков по золотому углу 137,5°, разброс угла и длины по номеру вида,
  светлое горло и насыщенный кончик, свечение за головкой, тычинки;
- ветер: общий наклон стебля + покачивание листьев и головки, перерисовка ~30 к/с
  (только когда сад на экране и окно в фокусе);
- оттенки видов ограничены милой палитрой из девяти цветов плюс сдвиг — иначе сырой
  `id·137.5` часто попадал в мутные коричнево-оливковые зоны;
- модель используется везде: сад, открытки, миниатюры гербария, обучение.

Старые 3 651 спрайт (`plant_<вид>_<стадия>.png`) **вынесены в `_sprites_archive/drawable-nodpi`**
и больше не пакуются в APK. В `res/drawable-nodpi` остались только 20 медалей и
`ic_launcher_fg.png`. Это уменьшило APK с 39,2 МБ до **0,6 МБ**.
Архив спрайтов сохранён — при желании можно вернуть.

Открытки рисуются кодом (`Postcard.java`) в 2× (2160×2700): бумажная фактура,
двойная рамка с внутренней тенью, золотой номер, параметрический цветок в тон фона,
серифное имя, дата и пожелание. Сохраняются через MediaStore в `Pictures/Сад`,
на Android 8–9 — файловый путь + WRITE_EXTERNAL_STORAGE (maxSdkVersion 28).
Темы: шесть палитр в `Theme.java` — «Ночной сад» (тёмно-зелёная), «Обсидиан»
(чёрный + белое свечение), «Лаванда» (фиолетовая), «Кавай» (светлая розовая),
«Светлая» (спокойный синий на светло-сером) и «OLED» (настоящий `#000000`, без
свечения и ярких заливок — минимум излучения на OLED-экранах).
Переключатель — в настройках; смена темы перезапускает `MainActivity`, потому что
цвета вкомпилированы во вью при создании. Для светлой темы берётся
`Theme.Material.Light` и тёмные иконки в строке состояния.

## Принятые решения / чего НЕ делать
- механику не менять без явной команды
- копию APK на рабочем столе не делаем: после изменений проекта публикуем в GitHub
  через `publish.ps1` (правило от 25.10.2026)
- каждое изменение попадает пунктом в `Changelog.java` (экран «История изменений»
  в настройках); даты — реальные дни работы, а не даты версий
- не делать «смену вида за очки» (было, откатили)
- свайп не должен работать над шапкой и нижней панелью
- открытки не перекрашивать под темы (но в 7.7 фон подстроен под оттенок цветка
  по явной просьбе — палитра и механика при этом не менялись)

## Известные ограничения
- проверено на HONOR PTP-N49 (Magic7 Pro), Android 16: все 5 вкладок, настройки,
  магазин, гербарий, полив, сбор цветка, датчик `honor_step_count` отдаёт события
- ориентация закреплена портретная: в альбомной кольцо шагов обрезалось снизу,
  а карточка растения и блок воды становились недоступны
- Android 8–9 требуют разрешение на запись для сохранения открыток
- виджет обновляется службой или системой (~30 мин), не мгновенно
- полная сборка на ПК ~62 с (все ресурсы) и ~13 с после правки кода;
  на телефоне — 4–6 минут, поэтому сборка перенесена на ПК
- цветение параметрической модели проверено на «ромашковом» архетипе (лепестки, листья,
  ветер). Колос лаванды, чаша тюльпана, звёзды, кристалл и колокольчик используют те же
  примитивы, но каждый вид на экране не проверялся — для этого нужно менять вид в сейве
- сад перерисовывается ~30 к/с ради ветра: это работает только когда сад на экране,
  но расход батареи на открытом саду выше, чем без анимации
- удаление 3 651 спрайта из APK сделано переносом в `_sprites_archive`; при возврате
  их в `res` APK снова вырастет до ~39 МБ

## Исправленные баги (чтобы не повторить)
- стадия 1 показывала семя: `Sprites.get(...,stage-1)` при stage=1 давал 0, а 0 трактовался как семя.
  Теперь семя запрашивается только при stage==0, иначе спрайт `plant_<вид>_<stage-1>`.
- график истории: всегда 7 слотов (сегодня-6 … сегодня), пустые дни — заглушки;
  подписи значений над всеми ненулевыми столбиками, высота графика 104dp.
- даты графика считаются календарём (Calendar), не через эпоху: иначе в UTC+3 слот съезжал на день.
- сад: «земля» рисовалась эллипсом в полосе кнопки и торчала из-под неё бурой полосой,
  а кнопка срезала основание стебля. Теперь земля не рисуется вовсе — подложка и тень
  уже есть внутри спрайта (`plant_*.png`), а цветок ставится ВЫШЕ кнопки.
- имена цветов: все прилагательные были женского рода — «Огненная мак», «Снежная колокольчик».
  Добавлен `Species.ADJ_M` (мужской ряд) и `MASC[]` по формам; 16 из 24 форм теперь
  согласованы. Проверка `NameCheck`: 365 видов, 365 уникальных имён.
- гербарий: «1 цветов в коллекции» → склонение по числу (`flowersWord`), а сырая дата
  `2026-10-24` → «24 октября 2026».
- всплывающее «Достижение: …» накрывало кнопки диалога открытки; теперь копится
  в `pendingAch` и показывается после закрытия диалога.
- уже собранные открытки хранят имя на момент сбора: после правки рода старые карточки
  остаются со старым именем, новые — с правильным.

### 7.7 — дизайн-проход (геометрия, типографика, палитра, движение, цветок, карточки)
- кольцо шагов: деления торчали за радиус на 29dp при запасе 20dp и срезались краем
  холста. Теперь деления начинаются в 11dp от дуги и укорочены (7dp/4.5dp).
- график: линия цели рисовалась до столбиков и сплошной — «врезалась» в сегодняшний
  столбик. Теперь она пунктирная и поверх; подпись высокого столбика рисуется тёмной
  внутри него, иначе светлая на зелёном не читалась.
- контраст подписей: старый `FAINT #4E6B61` давал 3,3:1 при норме 4,5:1. Введена шкала
  из четырёх ступеней, самая тихая ~5,3:1.
- высоты контролов были 34/38/40/42/46 — приведены к 52 (главная) / 46 (вторичные) / 52 (строки).
- текст на Canvas рисовался по базовой линии, подобранной числом; добавлен
  `Ui.baseline(paint, centerY)` и применён в саду, заданиях, графике.
- палитра: тёмная, но тёплая («ночной сад»), добавлены розовый и лаванда; 40+
  захардкоженных цветов заменены на константы `Theme`. Поймана регрессия: фон невыбранной
  вкладки был захардкожен цветом старой панели и после осветления стал виден под всеми пунктами.
- движение: пружинные переходы вкладок, «набегающие» цифры шагов, пружинка цветка
  на полив, конфетти при сборе (48 блёсток). Диалог открытки открывается через 0,8 с —
  иначе он закрывал конфетти.
- параметрический цветок (`KawaiiPlant`): четыре пойманных бага — самопересекающийся
  контур зубчатого листа («бантик»), незеркальные листья, полупрозрачные лепестки
  (альфа `Paint` от предыдущих `setColor` умножала цвет) и мутные оттенки видов.
- открытка: 2× (2160×2700), бумажная фактура, внутренняя тень, золотой номер,
  параметрический цветок в тон фона. Миниатюры гербария и обучение — тем же рендером.
- APK уменьшен с 39,2 МБ до 0,6 МБ переносом 3 651 спрайта в `_sprites_archive`.

### 8.6 — меньше трения, коллекция, резервная копия
- **автосинхронизация шагов**: кнопка «Обновить шаги» убрана. Датчик читается при
  открытии, при возврате в приложение и раз в минуту, пока открыта вкладка «Шаги».
  Вместо кнопки — спокойная строка «обновлено только что / N с назад»; по ней можно
  обновить вручную, если датчик отстал.
- **экран «Коллекция»** (`CollectionView`, `CollectionActivity`): сетка всех 365 видов,
  собранные цветные с акцентной рамкой, остальные — силуэтами (тот же параметрический
  рендер через PorterDuff-фильтр). Фильтры «Все / Собраны / Осталось», прокрутка
  с инерцией, нажатие на собранный вид открывает открытку с сохранением.
  Вход: профиль → «Коллекция» и тап по полосе букета в саду. Список сохранённых
  открыток остался отдельным экраном (`GalleryActivity`) — ссылка «открытки ›» в шапке.
- **резервная копия**: `Backup.java` + системный выбор файла (SAF). Сохранение в любой
  файл и восстановление с подтверждением; разрешений не требует, работает с 8 по 16.
  Старый мёртвый код (`exportSave`/`importSave` в MainActivity) удалён — он никем не
  вызывался и писал напрямую в /sdcard/Download.

### 8.7 — композиция, тактильность, анимация чисел, крупный шрифт
- **Экран шагов пересобран**: кольцо 206dp, график компактнее (88dp), под графиком
  появилась строка «до лейки N шагов» (раньше это было видно только в саду).
  Две распорки по краям держат композицию: герой-блок в верхней половине,
  карточка воды/серии — у нижнего края. Строка «обновлено…» переехала под карточку.
- **Тактильный отклик** (`Haptics`): 26 мс при смене вкладки и поливе, 45 мс при сборе
  цветка; антидребезг 35 мс. Разрешение VIBRATE добавлено в манифест.
- **Анимация чисел** (`CountUp`): очки и вода «набегают» за 420 мс, как шаги.
  Скачок больше 500 ставится мгновенно (после восстановления копии).
- **Карточка воды** обновляется и после полива в саду (`refreshWaterCard`), раньше

### 9.1 — анимация полива
Кнопка «Полить» больше не даёт мгновенный рост. Теперь `GardenView.water()` запускает
последовательность 950 мс: лейка въезжает справа, наклоняется, из носика летит струя
капель, лейка уезжает — и только после этого растение переходит в новую стадию и
пружинисто подрастает (`pulse`). Пока идёт полив, растение и точки стадий рисуются
в прежнем состоянии (`stageBefore`), поэтому рост видно как результат полива.
